# Пререндер SPA: мета и текст в исходнике, без SSR

У клиентского SPA все адреса отдают один `index.html`: один `<title>`, пустой
`<div id="root">`, ноль описаний. Google это рендерит, Яндекс — хуже и позже, а
мессенджеры и соцсети **не исполняют JS вообще** — ссылка разворачивается пустой
карточкой.

Переписывать на SSR ради этого не нужно. Достаточно снять готовый HTML с уже
работающего сайта.

## Один источник правды

Мета ставит **само приложение** — в той же единственной точке, где меняется
экран. Тогда пререндер просто снимает результат, и второго словаря текстов не
возникает.

    applyScreenMeta(screen)   // title, description, canonical, og:*, theme-color
      ← вызывается из useEffect по смене экрана

Тексты бери из тех же данных, что рисуют экран. Отдельный «словарь для SEO»
разъедется с сайтом на первой же правке.

## Пререндер

Сборка → поднять превью → обойти адреса настоящим браузером (Playwright обычно
уже стоит для тестов) → записать `dist/<path>/index.html`.

🔴 **Снимать HTML только после того, как движение доиграло.** Экраны приезжают
анимацией; снимок раньше времени записывает `opacity: 0` и `clip-path: inset(100%)`
прямо в файл — для краулера страница остаётся пустой, а глазами всё правильно.
Ставь проверку в сам скрипт:

    const invisible = [...document.querySelectorAll('#root *')]
      .filter(n => getComputedStyle(n).opacity === '0' && n.getBoundingClientRect().width > 0).length
    if (invisible) throw new Error('снимок сделан до конца движения')

🔴 **Список адресов берётся из приложения**, а не пишется в скрипте руками:
обойти главную, собрать ссылки/идентификаторы из DOM. Руками написанный перечень
забывают обновить ровно тогда, когда добавляют страницу.

🔴 **Гидратация не нужна.** Обычный `createRoot` перерисует `#root` поверх
снимка. Гидратация требует совпадения разметки до узла, а на живой странице
бывают canvas, перехват прокрутки и анимации — первое расхождение даст
предупреждение в консоли у посетителя.

## robots.txt и sitemap.xml

Собираются тем же прогоном, из того же списка адресов — иначе карта сайта
переживёт страницу, которую удалили.

## Отдача на Apache: две ловушки

🔴 **Пререндер создаёт ПАПКИ, и сервер начинает добавлять слеш.** Появился
`/a3/index.html` → появилась папка `/a3` → запрос `/a3` отвечает **301** на
`/a3/`. Адреса сайта меняются сами собой, а они обычно уже проиндексированы.
Лечится `DirectorySlash Off`.

🔴 **Порядок правил.** Правило «отдать `<path>/index.html`, если он есть» обязано
стоять ВЫШЕ проверки «путь существует» — иначе запрос к папке уходит в редирект,
не доходя до вашего правила.

    DirectorySlash Off
    RewriteCond %{DOCUMENT_ROOT}%{REQUEST_URI}/index.html -f
    RewriteRule ^(.+?)/?$ /$1/index.html [L]
    RewriteCond %{REQUEST_FILENAME} -f
    RewriteRule ^ - [L]
    RewriteRule . /index.html [L]

Заодно: SPA-fallback обычно отдаёт `200` и HTML на **любой** несуществующий файл,
включая `/assets/...`. Из-за этого не работают резервные адреса картинок, а
поиск получает бесконечный запас soft-404. Выведите каталог ассетов в честный
404.

## Сборка затирает пререндер

`vite build` чистит `dist`. Если деплой собирает и льёт, а пререндер запускается
отдельно, легко выложить чистый шаблон поверх готовых страниц. Порядок жёсткий:
**build → prerender → upload**, и в скрипте выкладки этот порядок должен быть
записан, а не держаться в голове.

## Проверка

Сторож читает **файлы сборки**, а не ответы превью: локальный `vite preview`
отдаёт `dist/a3/index.html` только по адресу со слешем, а на хостинге за это
отвечает `.htaccess`, которого у превью нет.

Проверяй: у каждого адреса свой `<title>`, ни один не повторяется, есть
`description` разумной длины, `canonical`, `og:image`, иконка и кусок настоящего
текста страницы. И отдельно — что правило отдачи лежит в `.htaccess`.
